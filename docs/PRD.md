# ODOQ — One Day One Quote (기획 초안 v0.2)

> 오늘 하루의 감상을, 남이 읽어도 의미 있는 한 구절로.

작성일: 2026-09-12 / 상태: 초안
v0.1 → v0.2 변경: 1일 1개 **강제 폐지**, 글자 수 500자, 시딩→액티베이션 로드맵 구체화, 법률 요건 문서 추가

---

## 1. 제품 정의

| 항목 | 내용 |
|---|---|
| 한 줄 정의 | 하루의 감상을 짧은 구절로 남기고, 다른 사람의 구절을 읽고 팔로우하는 앱 |
| 일기와의 차이 | 사건 기록(무엇을 했는가)이 아니라 **감상·통찰의 언어화**(무엇을 느꼈는가). 남이 읽어도 성립하는 범용적 문장 |
| 작성 규칙 | 하루 1구절이 **권장 리듬**이지 제약이 아님. 여러 개 써도 되고, 안 써도 됨 |
| 길이 | 최대 500자 |
| 소셜 | 팔로우 + 공감. **댓글 없음** |
| 성장 모델 | 시딩(Seeding) → 액티베이션(Activation) → 리텐션 |

### "일기가 아니다"를 제품으로 강제하는 장치

의도만으로는 유저가 일기를 쓴다. 아래 3개가 실제 강제 장치다.

| 장치 | 구현 |
|---|---|
| 기본 공개 | 신규 글 기본값 `public`. 비공개는 의도적 선택 |
| 에디터 카피 | "오늘 무슨 일이 있었나요?"(X) → "오늘 하루가 남긴 한 문장은?"(O) |
| 시드 콘텐츠 톤 | 초기 1,000~2,000구절이 톤을 결정한다. 시드가 일기면 서비스도 일기가 된다 |

> 리스크(확인 필요): 500자는 "구절"이 아니라 **짧은 글**의 분량이다. 500자를 허용하면 상당수가 일기로 수렴할 가능성이 높다. 완화책 — 피드 카드는 4줄에서 접고(더보기), 첫 문장이 제목 역할을 하도록 설계. 강한 대안: 기본 200자 + "펼치기"로 500자까지.

## 2. 작성 메커니즘 (v0.2 핵심 변경)

| 항목 | 초안 | 근거 |
|---|---|---|
| 횟수 | 무제한 | 강제는 이탈 트리거. "못 쓴 날"의 죄책감 제거 |
| 대표 구절 | 하루에 1개를 **오늘의 구절**로 지정(첫 글이 자동 지정, 변경 가능) | 앱 이름·캘린더·프로필 그리드의 단위를 유지 |
| 캘린더 표시 | 날짜 칸에는 대표 구절만. 추가 글은 날짜 상세에서 |
| 스트릭 | 연속일수 대신 **누적 작성일 수**("134일 기록") | 끊기면 0이 되는 지표는 이탈을 만든다 |
| 리마인더 | 1일 1회, 사용자 지정 시간, 끌 수 있음 | 광고성 아님(§법률 문서 참조) |
| 수정 | 작성 후 24시간 내 | 감상의 시점 보존 |

> 정체성 리스크: "One Day One Quote"라는 이름과 "횟수 무제한"은 어긋난다. 대표 구절 지정으로 봉합하는 것이 이번 초안의 답이다. 이 장치를 빼면 그냥 짧은 글 SNS가 된다.

## 3. 성장 로드맵 — Seeding → Activation

### Phase 0. 시딩 (출시 전 4~6주)

| 항목 | 내용 |
|---|---|
| 목표 | 공개 전 **시드 크리에이터 50~100명 / 구절 1,000~2,000개** 확보 |
| 모집 | 초대코드 기반 클로즈드 베타. 글쓰기 커뮤니티·뉴스레터 필자·북스타그램 운영자 대상 |
| 요청 | 2주간 하루 1구절 (1인 14구절 × 80명 ≈ 1,100개) |
| 보상 | 초기 크리에이터 배지, 추천 피드 우선 노출, 앱 크레딧에 이름 |
| 톤 가이드 | 시드 크리에이터에게 "일기가 아닌 감상" 예시 20개 제공 |
| 산출물 | 토픽 태그가 붙은 시드 풀 (내부 큐레이션용, 유저에겐 미노출) |

### Phase 1. 액티베이션 (신규 유저 첫 5분)

```
로그인 → 핸들 설정 → 관심 토픽 3개 이상 선택
  → 추천 유저 카드 (토픽별 8~12명) → 최소 3명 팔로우 (건너뛰기 가능)
  → 팔로잉 피드가 이미 채워진 상태로 진입
  → 첫 구절 작성 유도 (스킵 가능, 24h 내 리마인더)
```

- 추천 없이는 팔로잉 피드가 빈 화면 → **온보딩 팔로우가 액티베이션의 전부**
- 팔로우 최소 3명은 UI 유도만, 하드 블로킹 금지(이탈)
- 토픽 예시: 일상의 발견 / 관계 / 일과 성장 / 불안과 위로 / 책과 문장 / 계절

### Phase 2. 리텐션

리마인더 푸시(시간 지정) / 공감 알림 / 새 팔로워 알림 / 주간 다이제스트("이번 주 내 구절 3개 + 가장 공감받은 구절")

### Phase 3. 그로스 (v1.1)

구절을 이미지 카드로 만들어 외부 공유. **실제 성장 엔진은 여기일 가능성이 높다** — 인스타그램 "글스타그램" 소비 행태와 직접 연결. v1에서 제외했지만 우선순위는 v1.1 최상단.

### 추천 알고리즘 초안 (v1은 휴리스틱)

```
추천 후보 = 공개 계정
  AND 최근 14일 작성 3회 이상          -- 활동 중인 사람만
  AND 토픽 일치(유저 선택 토픽 ∩ 작성자 토픽)
  AND 차단·이미팔로우 제외
정렬 = (최근 30일 공감 수 / 글 수) 가중 + 신규 크리에이터 보정
```

ML 없음. 초기 추천 풀은 **수동 큐레이션 화이트리스트**로 시작한다.

### 액티베이션 지표

| 지표 | 목표(가설) |
|---|---|
| 온보딩 완료율 | 70% |
| 팔로우 3명 이상 달성률 | 60% |
| 가입 후 24h 내 첫 구절 작성률 | **40%** (가장 중요한 단일 지표) |
| D7 리텐션 | 25% |
| 주간 작성일 | 3일 이상 / 활성 유저 |

## 4. MVP 범위

### In scope

| # | 기능 | 설명 |
|---|---|---|
| F1 | 계정 | Apple/Google 로그인, 핸들·닉네임, **만 14세 이상 확인** |
| F2 | 구절 작성 | 최대 500자, 공개/비공개, 횟수 제한 없음, 대표 구절 지정 |
| F3 | 수정/삭제 | 24시간 내 수정, 삭제는 상시 |
| F4 | 내 기록 | 캘린더(대표 구절) + 리스트 |
| F5 | 피드 | 추천 / 팔로잉 2개 탭 |
| F6 | 팔로우 | 팔로우·언팔로우, 팔로워/팔로잉 목록 |
| F7 | 프로필 | 공개 구절만 노출 |
| F8 | 공감 | 1종. 댓글·DM 없음 |
| F9 | 안전 | 신고, 차단, 숨기기, 계정 삭제 |
| F10 | 알림 | 리마인더, 공감, 새 팔로워 (각각 on/off) |
| F11 | 온보딩 | 토픽 선택 → 추천 팔로우 |
| F12 | 법적 고지 | 약관·개인정보처리방침 동의, 신고 처리 절차, 권리침해 신고 창구 |

### Out of scope (v1 이후)

댓글, DM, 검색/해시태그, 이미지 첨부, 공유 카드(v1.1 최우선), 웹, 다국어, 결제.

## 6. 기술 스택 (제안)

| 레이어 | 선택 | 근거 |
|---|---|---|
| 앱 | React Native + Expo | iOS/Android 동시, OTA, 푸시 내장 |
| 상태 | TanStack Query + Zustand | 서버/UI 상태 분리 |
| 백엔드 | Supabase (Postgres + Auth + RLS) | 팔로우·피드가 관계형에 적합, RLS로 공개범위 강제 |
| 푸시 | Expo Push | |
| 분석 | PostHog / Amplitude | 액티베이션 퍼널 계측이 필수 |
| 데이터 소재지 | **국내 리전 우선 검토** | 개인정보 국외 이전 고지 부담 회피 (§LEGAL) |

> 리스크: Supabase는 기본적으로 해외 리전이다. 국내 유저 개인정보의 국외 이전은 **처리방침 고지 + 동의 또는 고지 요건**이 붙는다(법률 검토 필요). 대안은 국내 클라우드(NCP/AWS 서울) + 자체 API. MVP 속도와 법무 부담의 트레이드오프이며, **출시 전 반드시 결정해야 하는 항목**이다.

## 8. 미결정 사항

1. 글자 수: 500자 확정 vs 기본 200자 + 펼치기 500자
2. 데이터 리전: Supabase(해외) vs 국내 클라우드 — 법무 영향 큼
3. 토픽 태그를 유저에게 노출할 것인가(작성 시 태그 선택) vs 내부 추천용으로만 사용
4. 준익명(핸들) 전제 확정 여부 — 지인 기반 요소 도입 시 개인정보 이슈 증가
5. 시드 크리에이터 보상의 금전성 여부 (금전 지급 시 원천징수·계약 필요)
6. 서비스명 확정 (`ODOQ` / `One Day One Quote`) 및 상표 출원 여부
